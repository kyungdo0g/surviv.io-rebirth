# Puzzles, buttons, doors and scheduled unlocks

> Every puzzle in survev `shared/defs/puzzles.ts`, every building `puzzle` block, every obstacle with a `button` or `door` block (control panels, switches, bottles, planters, recorders, wheels, class pods, air drops, vats) and the timed unlock system, with the server and client logic step by step.
> Original v0.8.82 values come from the client defs in the 2026 relaunch bundle (`kong/relaunch-client-defs`); the server logic is survev's reconstruction. Bunker layouts are in bunkers.md, buildings in buildings.md.

## Puzzle engine

- A building opts in with a `puzzle` block: `name` (key into `Puzzles`), `completeUseType` (child obstacle type to trigger), `completeUseDelay`, `completeOffDelay`, `errorResetDelay`, `pieceResetDelay` and `sound{fail,complete}` [src:survev/shared/defs/mapObjects/buildings/buildingDefs.ts:86-97] [H]
- Pieces are child obstacles placed with a `puzzlePiece` label; `Puzzles[name]` is the ordered list of labels that solves it [src:survev/shared/defs/puzzles.ts:1-22] [src:survev/shared/defs/mapObjects/buildings/buildingDefs.ts:67-76] [H]
- Puzzle buildings are dynamic and keep `solved`, `errSeq`, `inputCode[]` and three tickers (reset, complete, idle reset) [src:survev/server/src/game/objects/building.ts:35-60] [src:survev/server/src/game/objects/building.ts:231-242] [src:survev/server/src/game/map.ts:1978-1980] [H]

### Step by step

1. A player uses a piece (a button obstacle, normally `useOnce`): `useButton` flips `onOff` to on, bumps `seq`, disables the piece (`canUse` false) and, because it is on and has a `puzzlePiece`, calls `parentBuilding.puzzlePieceToggled(piece)` [src:survev/server/src/game/objects/obstacle.ts:756-812] [H]
2. Input is ignored while a reset ticker runs; otherwise the idle ticker is cleared and the label is appended to `inputCode` [src:survev/server/src/game/objects/building.ts:435-452] [H]
3. On Woods (`woodsMode`) the name `bunker_eye_02` is swapped for `bunker_eye_02_woods` before the lookup [src:survev/server/src/game/objects/building.ts:447-449] [H]
4. If `inputCode` joined with '-' equals the code: `solved` = true, the presser is remembered, a parent structure whose `interiorSound.puzzle` matches switches to its alternate track, `startReset(completeOffDelay)` locks every piece, and `completeTicker` = `completeUseDelay` [src:survev/server/src/game/objects/building.ts:453-466] [H]
5. If the input is as long as the code but wrong: `errSeq`++ (clients play the fail sound) and `startReset(errorResetDelay)` [src:survev/server/src/game/objects/building.ts:467-472] [H]
6. Otherwise `idleResetTicker` = `pieceResetDelay`; if no further piece is used before it runs out, `errSeq`++ and the puzzle resets after `errorResetDelay` [src:survev/server/src/game/objects/building.ts:472-474] [src:survev/server/src/game/objects/building.ts:283-290] [H]
7. When the reset ticker ends, `resetPuzzle` clears the input and sets every piece back to off with `canUse = !solved`, so a solved puzzle stays locked [src:survev/server/src/game/objects/building.ts:486-523] [H]
8. When `completeTicker` ends, every direct child obstacle of type `completeUseType` is triggered: doors toggle, buttons are pressed, anything else is killed with the presser as source (Twins blue plates explode) [src:survev/server/src/game/objects/building.ts:247-281] [H]
- Client: on a new `errSeq` the building plays `sound.fail` at the nearest piece (muffled); on `solved` it plays `sound.complete` once unless it is "none"; solved puzzle ids are remembered so late joiners hear nothing [src:survev/client/src/objects/building.ts:389-436] [H]
- Client buttons: each `seq` change plays `sound.on` or `sound.off` at the obstacle (muffled) and shows `useImg` while on, `offImg` while disabled [src:survev/client/src/objects/obstacle.ts:270-280] [src:survev/client/src/objects/obstacle.ts:343-371] [H]

### Puzzle notes

- Halloween Eye code = bunkers in release order; recording log_01 hints "Six built, six found. The first in, the last out... First built... last found." [src:fandom/Eye_Bunker] [src:wikigg/Recorders] [M]
- Fandom: Woods originally had its own 10-panel code; v0.9.0a "Dodge This" switched Woods to the Halloween code and recorders, which is after v0.8.82 (post-0.8.82) [src:fandom/Eye_Bunker] [M]
- Eye vault opens about 6 s after the code (fandom); survev: 5.25 s complete delay + 0.1 s door delay [src:fandom/Vault_Door] [src:survev/shared/defs/mapObjects/obstacles/buildingObjsDefs.ts:455] [M]
- Chrysanthemum room-two history: 0.6.7 shipped a 12-planter code (harmony, clothes, growth, flower, rice, water, book, leaves, moon, gods, frost, priest per fandom); 0.6.91 replaced it with 4 crates and a hand-opened vault door, which is the v0.8.82 state [src:fandom/Chrysanthemum_Bunker] [src:kong/relaunch-client-defs] [M]
- In v0.8.82 `vault_door_chrys_01` is usable by hand (4.1 s delay, opens once); survev locks it (`canUse` false, `locked`) for its fork puzzle [src:kong/relaunch-client-defs] [src:survev/shared/defs/mapObjects/obstacles/buildingObjsDefs.ts:402] [H]
- The aged chrys `vault_door_chrys_02` has `canUse` false and its puzzle has no pieces, so it never toggles; fandom describes it as already open [src:survev/shared/defs/mapObjects/obstacles/buildingObjsDefs.ts:423] [src:fandom/Chrysanthemum_Bunker] [M]
- Saloon: solving stops the piano music, plays a high note and crashes the piano keys (`piano_02`) and the secret door slides open; the bottles are indestructible switches with a 1.25 interaction radius [src:fandom/Saloon] [src:survev/shared/defs/mapObjects/obstacles/interactableDefs.ts:417-432] [src:survev/shared/defs/mapObjects/structureDefs.ts:564-597] [H]
- Fandom lists the gun mount, a wood barrel and a column as unused saloon "pieces"; in the def the barrel and mount carry labels but are not buttons, so they can never be pressed [src:fandom/Saloon] [src:survev/shared/defs/mapObjects/buildings/modeBuildingDefs.ts:6091] [H]
- Club bathhouse switch: fandom notes it never springs back after use; solving `club_02` also swaps the club music to `club_music_02` [src:fandom/Switch] [src:survev/shared/defs/mapObjects/structureDefs.ts:598-640] [H]
